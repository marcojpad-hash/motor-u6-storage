PROTOCOLO DE ESTUDIOS — TRAZABILIDAD, INERCIA, PROYECCIONES E INGENIERÍA INVERSA
V15.1 — ESPECIFICACIÓN REPRODUCIBLE

OBJETIVO
Unificar el procedimiento para estudios de caso, ensayos y pruebas ciegas con cortes temporales. En cada corte se registra qué se sabía, qué mostró el sistema, qué hipótesis se congeló, qué se apostó, qué se proyectó, qué ocurrió después y qué aprendió la ingeniería inversa.

FLUJO
HECHO/FUENTE → MAPEADO → INPUT CONGELADO → ENGINE/ANÁLISIS → CAMPO + CURVAS + FULL TRACE → LECTURA DEL CORTE → HIPÓTESIS PROSPECTIVA CONGELADA → APUESTA EXPLÍCITA → PROYECCIÓN 1 → DETECCIÓN/REGISTRO DE INERCIA → PROYECCIÓN 2 SI CORRESPONDE → NUEVO CORTE → VALIDACIÓN TEMPORAL → INGENIERÍA INVERSA → FEEDBACK METODOLÓGICO

1. REGLA TEMPORAL
Solo puede utilizarse la información disponible hasta el corte t para formular la hipótesis de t+1. La hipótesis queda congelada antes de revelar el dato siguiente.

2. NO APLASTAR LA SALIDA
Se conserva campo completo, curvas, Full Trace y movimientos relevantes. El Top-1 no sustituye la estructura completa.

3. INERCIA
La inercia no se supone. Se busca una continuidad observable entre cortes: una dirección, configuración, relación o movimiento que persiste.
Primero se mide. Después se formula una hipótesis de inercia.
Si aparece una regularidad cuantificable, se investiga su fórmula. No se declara una fórmula universal antes de medirla.

4. PRIMERA PROYECCIÓN
Desde t se formula una proyección hacia t+1. Debe indicar qué se espera observar, qué evidencia la apoyaría, qué la refutaría y qué sería un acierto parcial.

5. SEGUNDA PROYECCIÓN
Si llega t+1 y la dirección observada mantiene la inercia previamente identificada, puede formularse una segunda proyección hacia t+2. P2 es una nueva congelación y no una reescritura de P1.

6. HIPÓTESIS SIMULTÁNEAS
Si dos hipótesis siguen siendo compatibles, se conservan ambas. No se fuerza una ganadora por Top-1.
Puede existir H1 y H2 simultáneas para t+1 y otra rama condicionada a evidencia posterior. Cada rama conserva evidencia, refutadores, horizonte y criterios de evaluación.

7. LA APUESTA
Toda corrida prospectiva declara qué se está apostando: quién/configuración es, qué transición ocurrirá, qué línea persistirá, qué estado aparecerá, qué dirección dominará u otra variable definida explícitamente por el estudio.
Cada apuesta debe tener criterio observable de acierto, acierto parcial y refutación.

8. PRUEBA CIEGA
En los estudios ciegos, el observador trabaja únicamente con la información disponible hasta el corte. Se congelan hipótesis, apuesta, proyección y criterios antes de revelar el siguiente dato.

9. VALIDACIÓN
Al llegar el dato: comparar contra P1; clasificar acierto, parcial o refutación; medir si la inercia continuó; no modificar el freeze. Si la regla previa lo permite, formular y congelar P2.

10. INGENIERÍA INVERSA
Después de conocer el dato real: qué acertó; qué falló; qué señales estaban presentes; cuáles fueron ignoradas; a qué se prestó demasiada atención; si la inercia se sostuvo o se rompió; si P2 estaba justificada; y si la apuesta estaba bien definida.
La ingeniería inversa no reescribe el pasado.

11. FEEDBACK
El aprendizaje modifica el método para futuras corridas, no el dato histórico ni las hipótesis ya congeladas.

12. REPRODUCIBILIDAD
Conservar versiones y hashes, fuentes, inputs exactos, parámetros, Full Trace, hipótesis congeladas, apuestas, proyecciones, resultados reales, validación, ingeniería inversa y limitaciones.
Si falta algo: FALTANTE / NO_VERIFICADO / RECONSTRUIDO.

13. PRINCIPIO DE CONTROL
No se busca demostrar retrospectivamente que el sistema “ya sabía” el resultado. Se mide qué podía formularse antes del siguiente dato, qué continuidad podía detectarse, hasta dónde podía extenderse una proyección y qué aprende el método cuando acierta o falla.

14. COMPATIBILIDAD V15.1
No exige modificar el Engine canónico. El predictor de vecinos permanece lateral. La estabilidad Monte Carlo no se interpreta como probabilidad futura. La estructura circular/monomítica puede actuar como lente semántica sin imponer una secuencia lineal.

[EXPERIMENTAL] fórmula usada en una prueba separada.
[CANDIDATA] arquitectura discutida, no integrada.
[NO IMPLEMENTADA] aparece en documentos como parte futura o Grupo B.

No se modifica Engine_V5_CANONICO_SOLO.py ni patterns_final_v14.json.

I. MOTOR V5 — NÚCLEO BAYESIANO
============================================================

1. Incertidumbre contextual de un marcador [CANÓNICA]

Para un marcador m con confianza c_m:

    sigma_m(t) = 1 - c_m

Implementación exacta:
    Marker.uncertainty() = 1.0 - confidence

Fuente: Engine_V5_CANONICO_SOLO.py.

2. Actualización Bayesiana de una hipótesis [CANÓNICA]

Para probabilidad previa p y likelihood l:

    p' = [p l] / [p l + (1-p)(1-l)]

Antes:
    l <- max(0.001, min(0.999, l))

Si el denominador es cero:
    p' = p

3. Evidencia favorable [CANÓNICA]

Si un token tiene peso favorable w:

    l = w
    p <- Bayes(p, l)

4. Evidencia contraria [CANÓNICA]

Si un token tiene peso contrario w:

    l = 1 - w
    p <- Bayes(p, l)

5. Corrección por estado de evidencia de la ficha [CANÓNICA]

Multiplicadores:

    primary_verified       = 1.0
    secondary_verified     = 0.7
    outdated               = 0.5
    unverified             = 0.4
    contestado_academicamente = 0.4
    contradicted_partial   = 0.2
    contradicted            = 0.1

Transformación del peso original w:

    w_efectivo = 0.5 + (w - 0.5) * multiplicador

Si no existe estado conocido:
    multiplicador = 1.0

6. Epsilon / masa residual de incertidumbre [CANÓNICA]

Una vez por observación:

    p <- (1-epsilon)p + epsilon*0.5

El epsilon conceptual no debe confundirse con la tolerancia numérica de coma flotante.

7. Indeterminación [CANÓNICA]

Con umbral de indeterminación 0.1 y tolerancia numérica 1e-9:

    indeterminado <=> |p - 0.5| < 0.1 - 1e-9

8. Dirección [CANÓNICA]

    direction = 0, si indeterminado
    direction = +1, si p > 0.5
    direction = -1, si p < 0.5

9. Delta de hipótesis del corte [CANÓNICA]

Para marcadores m_1 ... m_n:

    delta_H(t) = (1/n) * sum_i sigma_i(t)

donde:
    sigma_i(t) = 1 - confidence_i

Si no hay marcadores:

    delta_H(t) = 0

10. Delta mínimo dinámico [CANÓNICA]

    delta_min(t) =
        delta_min_base
        + (delta_min_max - delta_min_base) * delta_H(t)

11. Sorpresa/dispersión [CANÓNICA]

Si hay menos de dos marcadores:

    sigma_sorpresa(t) = 0

Si hay n >= 2:

    sigma_sorpresa(t) =
        sqrt[(1/n) * sum_i (sigma_i(t) - mean_sigma)^2]

Es desviación estándar poblacional (pstdev), no muestral.

12. Azar interno [CANÓNICA]

Sea:

    spread = sigma_sorpresa(t) * sigma_sorpresa_scale

Entonces:

    p_azar(t) =
        clip(0.5 + U[-spread, +spread], 0, 1)

donde U es uniforme aleatoria.

13. Monte Carlo de p_azar [CANÓNICA]

Estimación inicial:

    sigma_estimada_inicial =
        sigma_sorpresa(t) + delta_min_base

    n_inicial =
        max(min_n, floor[(sigma_estimada_inicial/epsilon)^2])

limitado por:

    n_inicial <= max_n

Por defecto documentado:
    min_n = 50
    max_n = 200000
    batch = 200

Error estándar:

    SE = sigma_muestral / sqrt(n)

Se detiene cuando:

    SE < epsilon

o cuando se alcanza max_n.

14. P indeterminado [CANÓNICA]

    p_indet = 0.5

15. Peso de evidencia [CANÓNICA]

    peso_evidencia =
        max(0, 1 - delta_min(t) - sigma_sorpresa(t))

16. P final [CANÓNICA]

    p_final =
        peso_evidencia * p
        + delta_min(t) * p_indet
        + sigma_sorpresa(t) * p_azar(t)

con:

    p_indet = 0.5

p_final es estado del motor, NO probabilidad calibrada del futuro.

17. Convergencia interna del tablero [CANÓNICA]

Para hipótesis no indeterminadas:

    strength_h =
        (favor_h - contra_h) / (favor_h + contra_h)

Se toma signo y magnitud:

    signo_h = +1 si strength_h >= 0
              -1 si strength_h < 0

Se selecciona la mayoría por cantidad de signos.

Entonces:

    convergencia =
        (N_mayoría / N_decididas)
        *
        mean(|strength_h| en la mayoría)

No es una métrica de predicción futura.

II. CAMPO 244 / TRAZA
============================================================

18. Delta temporal de cada hipótesis [PLUGIN]

    Delta_i(t) = P_i(t) - P_i(t-1)

Para cada corte se conserva el vector completo de deltas.

19. Cambio de rango [PLUGIN]

Si rank_de y rank_a son posiciones ordinales:

    delta_rank = rank_de - rank_a

Un valor positivo significa que la hipótesis subió posiciones.

20. Interrelación entre hipótesis [PLUGIN]

Para dos series de deltas:

    r_ij =
      sum_t[(Delta_i(t)-mean_i)(Delta_j(t)-mean_j)]
      /
      sqrt(
        sum_t(Delta_i(t)-mean_i)^2 *
        sum_t(Delta_j(t)-mean_j)^2
      )

Es correlación de las trayectorias de delta.

Con menos de dos observaciones no se calcula.
Con varianza prácticamente cero el código devuelve 0.

El resultado se interpreta como POSIBILIDAD DE INTERRELACIÓN, no identidad causal.

21. Neto de una hipótesis [PLUGIN]

    neto_i = P_i(último) - P_i(primero)

22. Top-1 [PLUGIN]

    H_t = argmax_i P_i(t)

Es el letrero, no el hallazgo completo.

23. Movimiento [PLUGIN]

Para cada hipótesis:

    d_i(t) = P_i(t) - P_i(t-1)

Se ordenan por:

    |d_i(t)|

y se muestran los N_MOV principales.

    N_MOV = 3

24. Persistencia [PLUGIN]

Se buscan hipótesis distintas de H_t entre el Top-12 que cumplan:

    P_i(t) >= piso

Configuración:

    piso = 0.62
    N_PERSIST = 3

Las primeras tres se registran como "no_se_apagaron".

37. Solapamiento Top-K [PLUGIN]

Para conjuntos/listas A y B:

    overlap(A,B) = |A ∩ B| / max(|A|,|B|)

Casos:

    uno vacío -> 0

    H_quieta =
        [ |p_H(n)-p_H(n_prev)| <= 0.02 ]

        [ I >= 0.02 ]

40. N_min [PLUGIN]

N_min es el menor n para el cual la condición anterior se mantiene durante:

    m = 3

ventanas consecutivas.

41. Resolución creciente [PLUGIN]

    n_k = n_0 * 2^k

con:

    n_0 = 32

por tanto:

    32, 64, 128, 256, 512, ...

42. Fusible [PLUGIN]

    N <= 8192

Si se alcanza el fusible sin N_min:

    NO_ENCONTRADO_FUSIBLE

El fusible NO se interpreta como N_min.

43. Media de p_H en bootstrap [PLUGIN]

Para n réplicas:

    p_H(n) = (1/n) * sum_j p_H,j

44. Intensidad residual I [PLUGIN]

    I(n) = max(0.02, mean(I_j))

si existen valores I_j; de lo contrario:

    I(n) = 0.02

45. Ganador modal [PLUGIN]

Se selecciona el nombre con mayor frecuencia entre las réplicas:

    winner = mode(winner_j)

46. Top-K bootstrap [PLUGIN]

Se cuentan los nombres de los Top-K de cada réplica y se ordenan por frecuencia.

          {"etapa_id": "e0", "nombre": "...", ...},
          ...
        ]
      }
    }
  }

Para el matching, cada etapa debe proporcionar un estado codificado. Se aceptan
los campos "estado_monomito", "estado", "monomito", "codigo" o "stage".
Si no existe ninguno, el runner falla explícitamente: no inventa una codificación.

El archivo resultante contiene una corrida por cada prefijo e0..eN y el ranking
completo de las 15 referencias elegibles en ese corte.
"""

from __future__ import annotations

import argparse
import json
from pathlib import Path
from typing import Any, Dict, List, Tuple

from predictor_vecinos_prefijo_v1 import predict_next


STATE_FIELDS = ("estado_monomito", "estado", "monomito", "codigo", "stage")


def load_case(path: Path, case_id: str) -> List[Dict[str, Any]]:
    with path.open("r", encoding="utf-8") as f:
        data = json.load(f)

    if not isinstance(data, dict) or "casos" not in data or not isinstance(data["casos"], dict):
        raise ValueError("Formato no compatible: falta objeto 'casos'.")
    if case_id not in data["casos"]:
        raise ValueError(f"Caso no encontrado: {case_id}")

    case = data["casos"][case_id]
    if not isinstance(case, dict) or not isinstance(case.get("etapas"), list):
        raise ValueError("El caso debe contener una lista 'etapas'.")
    stages = case["etapas"]

    if len(stages) != 16:
        raise ValueError(
            f"ABORTADO: la escaleta cargada contiene {len(stages)} etapas; "
            "este runner exige exactamente 16. No se acepta una copia de 10 etapas."
        )

    return stages


def stage_code(stage: Dict[str, Any], index: int) -> str:
    for field in STATE_FIELDS:
        value = stage.get(field)
        if isinstance(value, str) and value.strip():
            return value.strip()
    raise ValueError(
        f"Etapa {index} ({stage.get('etapa_id', '?')}) no tiene un estado codificado "
        f"en ninguno de {STATE_FIELDS}. No se reconstruye por suposicion."
    )


def run(path: Path, case_id: str, current_index: int | None = None, top_n: int = 5) -> Dict[str, Any]:
    stages = load_case(path, case_id)
    codes = [stage_code(s, i) for i, s in enumerate(stages)]

    if current_index is None:
        current_index = len(codes) - 1
    if not 0 <= current_index < len(codes):
        raise ValueError("etapa_actual fuera de rango 0..15")

    runs = []
    for k in range(1, current_index + 1):
        result = predict_next(codes[:k], top_n=top_n)
        runs.append({
            "stage_current_id": stages[k - 1].get("etapa_id", f"e{k-1}"),
            "stage_current_name": stages[k - 1].get("nombre"),
            "prefix_length": k,
            "result": result,
        })

    return {
        "status": "ok",
        "case_id": case_id,
        "input_file": str(path),
        "validated_stage_count": 16,
        "current_index": current_index,
        "current_stage_id": stages[current_index].get("etapa_id", f"e{current_index}"),
        "current_stage_name": stages[current_index].get("nombre"),
        "runs": runs,
        "disclaimer": "Estimación por vecinos más cercanos entre 15 casos; no es una probabilidad poblacional real.",
    }


def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("escaleta", type=Path)
    ap.add_argument("caso_id")
    ap.add_argument("etapa_actual", nargs="?", type=int)
    ap.add_argument("--top", type=int, default=5)
    ap.add_argument("--out", type=Path, default=None)
    args = ap.parse_args()

    result = run(args.escaleta, args.caso_id, args.etapa_actual, args.top)
    text = json.dumps(result, ensure_ascii=False, indent=2)
    if args.out:
        args.out.write_text(text + "\n", encoding="utf-8")
    else:
        print(text)


if __name__ == "__main__":
    main()

# 3. REGLAS ESTRUCTURALES DE LA ESCALETA PARA PREDICTIBILIDAD

• El runner exige exactamente 16 etapas.
• Rechaza explícitamente una escaleta de 10 etapas.
• Cada etapa debe aportar un estado codificado.
• Campos aceptados: estado_monomito, estado, monomito, codigo o stage.
• Si no existe un estado codificado, el runner falla; no reconstruye por suposición.
• El predictor se ejecuta sobre prefijos sucesivos e0..eN.
• Para cada corte se conserva el ranking de las referencias elegibles.
• La estimación por vecinos no debe presentarse como probabilidad poblacional.
• La escaleta de predictibilidad y la escaleta personal son artefactos distintos,
  aunque la segunda puede servir como entrada al runner cuando esté codificada.

Tres vistas simultáneas de un mismo sistema:

- ΔX_t=X_{t+1}-X_t
- dirección
- magnitud |ΔX_t|

La arquitectura contiene capas con funciones distintas:

2. RESOLUCIÓN ADAPTATIVA
Tortuga no debe aumentar resolución simplemente porque pueda.
La resolución aumenta cuando la resolución disponible todavía no permite distinguir una transición estructural.
Cuando aumentar resolución deja de cambiar lo relevante, se detiene.

3. PERSISTENCIA, ESTABILIDAD Y PREDICCIÓN NO SON LO MISMO
Persistencia, Top-1, aumento de peso, supervivencia a perturbaciones o meseta no demuestran por sí mismos el futuro.
Debe mantenerse la separación:
estado → estabilidad → trayectoria → predicción.

La fórmula congelada de Meta:
I_t = 0.998 I_{t-1} - 0.06

Fue evaluada en agosto mediante:
Predictividad = 1 - |Pred - Real| / Real

Resultado registrado: 98.59%.
Esto valida ese experimento bajo ese criterio; no demuestra una ley universal.
Las predicciones de septiembre deben compararse contra la realidad sin reajuste retrospectivo.

La transformación:
T_D(I_t) = D I_{t-1} + f_ext

encontró dinámicas diferenciadas.

Conclusión válida: no existe equivalencia directa bajo esa transformación.
No debe forzarse una equivalencia.

6. TRANSFORMACIÓN TEMPORAL k
Apareció un candidato de escala temporal cercano a k ~ 28.
No es una conclusión.
Es únicamente una transformación que puede ser sometida a prueba.

7. FIBONACCI / φ
En un caso de Fibonacci, distintas representaciones recuperaron la misma estructura:
x_t = x_{t-1} + x_{t-2}

Polinomio característico:
r² - r - 1 = 0

Raíz positiva:
φ = (1 + √5) / 2

AR2, SINDy y Z/Laplace convergieron hacia la misma estructura.
Esto muestra que una estructura puede reconocerse desde representaciones matemáticas independientes.

Límite metodológico: las variantes nuevas con ruido fueron generadas a partir de la estructura φ, por lo que demuestran reconocimiento/reversibilidad, no descubrimiento ciego.

La investigación dejó de ser simplemente “buscar una fórmula”.

La pregunta más precisa es:

modelos
→ representaciones
→ estructura/invariantes
→ nuevo modelo
→ verificación

Esto puede describirse provisionalmente como diagnóstico diferencial transversal de arquitecturas matemáticas.

No se afirma todavía que esta arquitectura completa sea una metodología nueva.

9. APRENDIZAJE METODOLÓGICO
Un experimento puede producir:
- pertenencia a una estructura,
- no pertenencia,
- necesidad de otra representación,

No es necesario que todas las fórmulas converjan ni que exista una fórmula universal para que el experimento produzca conocimiento.
